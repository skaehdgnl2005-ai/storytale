# /implement-task

태스크를 TDD 방식으로 구현하는 워크플로우.

## 사용법
```
/implement-task S12
```

## 워크플로우
1. `docs/TASK_BACKLOG.md`에서 해당 태스크(예: S12) 정보를 읽는다.
2. 의존 태스크가 완료되었는지 `docs/SESSION_LOG.md`에서 확인한다.
   - 미완료 의존성이 있으면 경고하고 중단.
   - 완료된 의존 태스크의 **"구현 요약"** 섹션을 읽어 실제 구현 상태를 파악한다.
3. `docs/contracts/`에서 관련 인터페이스를 읽는다.
4. 태스크에 **"시작 시 필수 읽기"**가 명시되어 있으면 해당 문서도 읽는다.
5. 테스트 파일을 먼저 작성한다.
6. `pytest {테스트파일}` 실행 → 실패 확인.
7. 구현 코드를 작성한다.
8. `pytest {테스트파일}` 실행 → 통과 확인.
9. `ruff check` + `ruff format` 실행.
10. 새 모듈 디렉토리를 생성했으면, 해당 디렉토리에 **README.md**를 작성한다:
    - 모듈 목적 (1~2줄)
    - 주요 클래스/함수와 역할
    - 사용 예시 (import 포함)
    - 테스트 실행 방법
11. `docs/SESSION_LOG.md`에 완료 기록 추가:
    - 완료된 것
    - 구현 요약 (주요 클래스/파일 위치/계약 대비 변경점/환경변수)
    - 다음 세션에 알려줄 것
    - 변경된 파일 목록
    - (프롬프트 관련 태스크면) 프롬프트 변경 이력
12. `docs/TASK_BACKLOG.md`에서 상태를 `[완료]`로 변경.
13. `docs/PROGRESS.md` 업데이트:
    - 해당 Phase 진행률 갱신 (프로그레스 바 + 숫자).
    - "현재 위치" 3줄(마지막 완료, 진행 중, 다음 착수 가능) 갱신.
    - 차단 테이블에서 해소된 의존성 제거.

## 주의사항
- 한 번에 파일 5개 이상 수정하지 말 것.
- 컨텍스트가 무거워지면 중간에 `/compact` 사용.
- 다른 모듈의 코드를 수정해야 할 것 같으면 멈추고 보고.
